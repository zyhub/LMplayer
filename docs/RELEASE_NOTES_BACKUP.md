### v1.7.25

```
## 🐞 修复：下载完成后状态迟迟不变「已完成」

**现象**
- 下载到 100% 后，进度条长时间不消失、状态迟迟不变成「已完成」
- 暂停后恢复下载，反而会立刻完成

**根因**
- 进度条由 `totalRead / totalLength` 计算，读完最后一个字节就显示 100%；而「进度条消失 + 状态变已完成」取决于 `removeTask` 与写库，它们被排在元数据处理 `postProcessDownloadedFile` **之后**
- 该函数内含 **两次同步网络请求**（拉取封面图、拉取歌词），即使失败也要各自走完超时，于是在「100% → 已完成」之间插入了数十秒纯等待
- 暂停后恢复会立刻完成，是因为字节已完整、跳过下载循环，且收尾网络请求已缓存或变快
- 配套问题：OkHttp 只设了 connect / read / write 超时（均为**单次 IO** 语义），缺少请求总时长上限，慢速响应的请求可以挂数分钟

**修复**
- **重排收尾顺序**：先写库 + `removeTask`（立刻变「已完成」、进度条立即消失），元数据内嵌移到其后在后台执行
- 新增 `postProcessLocalCoverOnly()`：仅本地读取 `cover.jpg`，让列表立刻有封面，不走网络
- 元数据内嵌用 `NonCancellable + Dispatchers.IO` 包裹 —— 标签写入是文件级写操作，用户此时暂停/取消若被打断会留下损坏的音频头
- 元数据失败不影响下载结果（音频已完整落盘、库记录已是 `DOWNLOADED`），仅记日志
- `NetworkClientFactory` 补 `callTimeout(300s)`，兜住长时间挂死的请求

**效果**
- 进度条到 100% 后**几乎立即**变为「已完成」（只等一次本地文件探测 + 两次数据库写入）
- 元数据（封面、歌词、ID3/FLAC 标签）仍在后台正常补全，不阻塞完成状态
```

### v1.7.24

```
## 🐞 修复
- **修复「退出应用时停止播放」在同一页面重复出现两次**：一次在「播放与启动行为」（正确位置），另一次误放在「界面外观与字体规格」下；两处读写同一偏好项，切换任一另一个立即同步，会被误当成两个独立设置
- **修复该设置副标题与实际默认值相反**：原文写「默认关闭（退至后台/桌面时继续放歌）」，而代码默认值是**开启** —— 用户会误以为退到后台就停播，实际不会
- **修复返回键行为不确定**：此前播放中按返回退到后台、**暂停中按返回却会退出并停播**，同一设置下同样的按键得到相反结果。现统一为「开关关闭时按返回一律退到后台」
- **修复「不保留活动」等场景误停播放**：`onDestroy` 中 `isFinishing` 为真时会停播，而它在系统回收 Activity 时同样成立。现只保留「用户明确要求退出」一个判据

## ✏️ 调整
- 「彻底退出应用并停止后台服务」按钮补注：**无论上方开关如何设置都会停播**，消除与该开关的语义冲突

## ✅ 实测验证（Android 9）
- 页面只剩一个「退出应用时停止播放」开关，副标题已更新
- 开关关闭 + 按返回：一次按键直接退到桌面，无 Toast，进程与服务存活
- 开关开启 + 双击返回：Activity 正常销毁、播放服务已停、回到启动器
- 清除数据模拟全新安装：默认值仍为开启，行为符合预期

## 🔍 锁屏播放专项排查（未改代码）
针对「锁屏导致播放暂停」的反馈做了专项验证：播放中锁屏 25 秒 / 断网息屏 30 秒 / 长息屏 60 秒，
播放位置分别前进 29 秒 / 31 秒 / 58 秒，速度稳定 1.0，WakeLock 持续持有，
日志无任何 pause / stop / 音频焦点丢失记录。
源码层亦不存在 `ACTION_SCREEN_OFF` 等锁屏监听 —— **锁屏不会停播**。
```

```
## 🐞 修复：下载完成后状态迟迟不变「已完成」

**现象**
- 下载到 100% 后，进度条长时间不消失、状态迟迟不变成「已完成」
- 暂停后恢复下载，反而会立刻完成

**根因**
- 进度条由 `totalRead / totalLength` 计算，读完最后一个字节就显示 100%；而「进度条消失 + 状态变已完成」取决于 `removeTask` 与写库，它们被排在元数据处理 `postProcessDownloadedFile` **之后**
- 该函数内含 **两次同步网络请求**（拉取封面图、拉取歌词），即使失败也要各自走完超时，于是在「100% → 已完成」之间插入了数十秒纯等待
- 暂停后恢复会立刻完成，是因为字节已完整、跳过下载循环，且收尾网络请求已缓存或变快
- 配套问题：OkHttp 只设了 connect / read / write 超时（均为**单次 IO** 语义），缺少请求总时长上限，慢速响应的请求可以挂数分钟

**修复**
- **重排收尾顺序**：先写库 + `removeTask`（立刻变「已完成」、进度条立即消失），元数据内嵌移到其后在后台执行
- 新增 `postProcessLocalCoverOnly()`：仅本地读取 `cover.jpg`，让列表立刻有封面，不走网络
- 元数据内嵌用 `NonCancellable + Dispatchers.IO` 包裹 —— 标签写入是文件级写操作，用户此时暂停/取消若被打断会留下损坏的音频头
- 元数据失败不影响下载结果（音频已完整落盘、库记录已是 `DOWNLOADED`），仅记日志
- `NetworkClientFactory` 补 `callTimeout(300s)`，兜住长时间挂死的请求

**效果**
- 进度条到 100% 后**几乎立即**变为「已完成」（只等一次本地文件探测 + 两次数据库写入）
- 元数据（封面、歌词、ID3/FLAC 标签）仍在后台正常补全，不阻塞完成状态
```
